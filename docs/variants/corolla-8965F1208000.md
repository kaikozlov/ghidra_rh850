# Corolla `8965F1208000` EPS investigation

> **Scope:** 2025 Toyota Corolla Hybrid EPS — a *different calibration* from the analyzed Sienna.
>
> **Document type:** variant record
>
> **Status:** active (field probes done; firmware not yet in hand)
>
> **Evidence source:** dynamic-probe (field) + firmware-static (none yet)
>
> **Confidence:** mixed — see buckets below

This page separates two evidence classes that must not be merged: **direct
field-probe observations** (a real Corolla answered on the bus) and
**firmware-static conclusions** (which require the actual bytes, not yet
obtained). Machine-readable row: `data/tss3_eps_variant_matrix.csv`, checked

## Confirmed by Corolla field probes

Observed on a live vehicle (source: calvinpark/openpilot
`tsk/COROLLA_INVESTIGATION.md`, Discord probe captures Jul 2026). These are
real observations, not hypotheses:

- **Application software ID:** `8965F1208000`
- **Secondary software ID:** `8A3111213000`
- **Diagnostic bus:** CAN-FD (bus 1 carries 32-byte frames; EPS is on bus 1,
  not bus 0/2)
- **Physical diagnostics:** request `0x7A1` → response `0x7A9`
- **Application DIDs observed:** `F181` = `8965F1208000` + `8A3111213000`
  (count `0x02`, two records); `F186` = session; `F18C` = serial
  `8965012N50E12H030731`
- **13 application SIDs answer:** `10,14,19,22,23,27,2E,31,36,37,3E,AB,BA`
  (`11/28/34/85` absent from extended)
- **SecurityAccess level `0x03`:** seed returned in extended session; stable
  within a session, regenerates across sessions, session-gated (default → NRC
  `0x7F`). Level `0x01` → NRC `0x7E` in extended.
- **`10 02` programming request** to `0x7A1` produces an **inconclusive
  timeout** (no NRC); session after = `0x01`.
- **`0x14`** crashes the diagnostic stack on subfunction probe.
- **`0x23`** validates addresses (NRC `0x31`) — unlike Sienna's inert echo.
- **SecOC:** sync ID `0x0F` observed; secured CAN IDs `0x2E4`, `0x131`,
  `0x344`. A 90-second READY capture saw 0 SecOC-signed EPS transmissions —
  consistent with ingress-only SecOC.

## Interpretation guarded by Sienna analysis

These are field observations whose *meaning* is constrained by the Sienna
firmware analysis but not yet confirmed for Corolla:

- **The `10 02` timeout is not decisive.** Sienna firmware predicts that a
  *successful* PROGRAMMING request also produces a client timeout (the reset
  overtakes the final `50 02`). `F186=0x01` post-timeout is likewise not
  decisive. The discriminating evidence — a bus-1 CAN capture during `10 02`
  to observe whether the EPS actually reset — is **missing**.
- **The level-`0x04` send-key probe is non-diagnostic.** It used a bootloader
  secret (`f05f36…`), not the application secret (`893e08…`); NRC `0x35` is
  expected even on Sienna. Whether the Corolla shares the Sienna application
  SA secret (`893e08418c741ffa2a9c044bffa55813`) is **UNTESTED**.
- A reset-window probe found no bootloader acceptance during manual reboot.

## Not yet checked

In priority order when firmware arrives:

1. Confirm MCU and two-region layout (cheap, decisive).
2. Locate the application service table and DID tables — is it the same
   17-SID schema, or the 13-SID subset the field probe saw?
3. Trace the application SecurityAccess path: is level 1 a stub? Is level 2
   functional? Where is the secret? **Does it match the Sienna `0x20840`
   secret?** (Field-probe this first — cheap.)
4. Locate the bootloader payload gate; are `SEED_KEY_SECRET` /
   `PAYLOAD_BUILD_SECRET` present at analogous offsets?
5. Scan for SecOC records; is the slot-4 key provisioned? (Corolla field
   evidence already shows `0x344` secured — absent on Sienna.)

## Current openpilot implications

Ingress-only SecOC (no signed EPS transmissions observed) is the most
immediately relevant finding for openpilot — it suggests the actuation path
may not require SecOC signing on this variant, but this needs confirmation
against the actual torque command path before any reliance.
