# Crown EPS `8965F3012000`

> **Status:** first-class analysis target from mruno's reported 2024 Toyota Crown Limited.
> **Source:** `community/mruno/`, acquired 2026-09-13.
> **MCU:** RH850/P1M-E `R7F701381`.

## Canonical images

The contributor supplied a fixed 2 MiB CodeFlash host buffer after the range
collector received 2,075,572 bytes. The complete populated physical CodeFlash is
the lower 1 MiB. Bytes `0x100000..0x1FABB3` in the received upper host range are
all erased `0xFF`; the unreceived `0x1FABB4..0x1FFFFF` tail is zero-filled
collector state and is not firmware.

`tools/targets/crown/builders/promote_crown_analysis_inputs.py` therefore promotes
only the complete lower physical image:

- CodeFlash: `firmware/crown-8965F3012000/CodeFlash.bin`, SHA-256
  `5b89fdbc69edc2f66ef8a557f88b08c758e3146bd4e90067320d7966812b1273`;
- DataFlash: `firmware/crown-8965F3012000/DataFlash.bin`, SHA-256
  `0c7b027900d4ac12a4e665e17c0575d44efb0ccfbcb6239416a40c8260c50872`.

## First-class project

`crown-8965F3012000` is registered in `data/analysis_targets.json`. Its committed
Ghidra snapshot was promoted only after two independent staged rebuilds produced
byte-identical inventories. The canonical corpus contains 5,874 functions.

The exact application entry remains `0x20880`. Target-native decompilation closes
its startup edge to `0x62BEE`. The context loader is `0x709E4` and sets:

```text
INTBP = 0x20200
EBASE = 0x20000
GP    = 0xFEBEB800
TP    = 0x23C98
SP    = 0xFEBE2000
```

The startup shadow-copy helper at `0x62AD4` is byte-identical to Camry F33's
`0x636D4` and copies CodeFlash `0x10000..0x17DEF` into LocalRAM beginning at
`FEBF7C00`.

## Exact Crown-vs-Camry boundary

`data/generated/crown_8965F3012000_camry_comparison.json` is regenerated from the
two canonical CodeFlash images. The first differing byte is at `0xA004`; the
boot core `0x0000..0x91FF` is byte-identical. Across the full 1 MiB, however,
621,353 bytes differ, so F3 family naming is not a license to transplant
application addresses blindly.

Several high-value architectural pieces do transfer exactly:

- payload-build root at `0xBFD8`, boot SecurityAccess root at `0xBFE8`, and
  application SecurityAccess root at `0x20840` are byte-identical;
- the 241-entry RDBI DID membership is identical (195 unique callbacks), with
  Crown's table relocated from Camry `0x2928C` to `0x28FA8`;
- command-5 synchronous wrapper: Camry `0x89BC2` -> Crown `0x87662`, exact
  138-byte body;
- command-5 dispatcher: Camry `0x89440` -> Crown `0x86EE0`, exact 150-byte body;
- freshness-48 packer: Camry `0x90566` -> Crown `0x8E006`, exact 120-byte body.

Target-native Ghidra additionally shows Crown `0x881C0` has the same command-5
engine structure as Camry `0x8A720`: it programs ICU-S command 5 after the same
state/input checks, with target-local internal callback/MMIO literal addresses.
This is strong evidence that the EPS-local signing architecture transfers; the
Crown resident still requires target-native address resolution.

### Important non-transfer: C7 ingress

Camry CodeFlash contains the hardware-formatted extended-CAN word `0x9FDC0002`
for `0x1FDC0002` twice. Crown CodeFlash contains it zero times. Therefore the
working Camry C7/XCP ingress must **not** be copied to Crown by assumption. The
next Crown-specific porting step is to recover its available host-to-resident
control ingress, then resolve the native B6 queue/buffer and post-receive / pre-
SecOC insertion point from this exact image.
