# Maintainer 2026 Camry field baseline

**Vehicle attribution:** maintainer-operated 2026 Toyota Camry
**Captured:** 2026-08-26
**Application F181:** `8965F3307000` / `8A3113303100`
**ECU serial:** `8965033K9011J2740743`
**Diagnostic route:** ELM327 parameter 1, logical bus 1, `0x7A1 -> 0x7A9`

This directory preserves the first identity-bound field baseline from the
maintainer's 2026 Camry. The source TSK session ran the observation-oriented
identity map while Not Ready to Drive, retained a roughly 60-second stationary
READY CAN capture, then exercised the bounded PROGRAMMING handoff probe and a
read-only XCP CONNECT probe.

The full TSK export also contains device/network/operational metadata that is not
needed for firmware/vehicle analysis. Instead of committing that wrapper, the
tracked corpus keeps the raw CAN oracle plus compact exact-value snapshots of the
three diagnostic results. `raw-20260826/MANIFEST.txt` pins every tracked source
file and the SHA-256 of the uncompressed CAN oracle.

## Immediate results

The EPS identifies as a new calibration not previously present in this repository:
`F181 = 02 || 8965F3307000 || 8A3113303100`. The same normal-harness route uses
physical request/response `0x7A1/0x7A9`. DEFAULT -> EXTENDED -> PROGRAMMING
succeeds and the diagnostic endpoint reappears on the same route; bootloader
F181 becomes the familiar `02 || 32*0x21` placeholder. These observations put the
Camry in the same broad Denso/P1M-E diagnostic family as the tracked Corolla/Sienna
specimens, but they do **not** establish the Camry's SecurityAccess secret,
authenticated RequestDownload geometry, `0x10F0` contract, RAM-exec window, or
ciphertext portability.

The READY CAN capture is similarly close to the H/F Corolla vehicle architecture.
Logical bus 1 carries `0x00F/8`, `0x025/32`, `0x030/32`, `0x090/32`, `0x0D7/32`,
`0x0AA/8`, `0x101/8`, `0x116/8`, `0x127/8`, `0x176/8`, and `0x51E/8` at compatible
widths/cadences, while buses 0 and 2 share the same 22-ID/DLC CAN-FD set seen in
the retained TSS3 Corolla route family. The old classic steering commands
`0x131/8` and `0x2E4/8` are absent. Protected `0x0B6/32` is also absent, but the
segment did not exercise stock LTA, so that is only a segment-level negative.

Several H/F-derived state formats transfer strongly at the wire level:

- all 6,188 `0x030` frames satisfy the exact H/F additive rule
  `B7 = low8(sum(B0..B6) + 0x38)`;
- the H/F `0x030` steering-torque encoding reconstructs a dynamic
  `-1.75..+1.80 N.m` range during the stationary capture;
- the H/F `0x025` steering angle/fraction/rate layout decodes coherently;
- Toyota checksums validate on every retained `0x101`, `0x127`, and `0x176`
  frame;
- `0x127` raw gear value is `0` throughout and is prior-art-compatible with P;
- most importantly, `0x51E B0[7]` transitions from `0` to `1` about 0.98 seconds
  into the READY capture. This is the first retained transition that strongly
  corroborates the H/F + Techstream `Ready Status` wire join on another TSS3
  vehicle family.

The XCP CONNECT-only probe sent `0x7F7` on the identified EPS route and observed
no usable `0x7F8` response. Treat that as a route/session negative, not proof the
vehicle has no XCP path anywhere.
