Procedure
- Vehicle began fully OFF/Park.
- UI-backed startup catcher was armed before POWER.
- Operator pressed brake + POWER normally.
- Catcher repeatedly offered EXTENDED, waited for the first completed positive
  50 03, then sent one 10 02.

- Classic 0x08A RAM oracle was installed directly from the caught bootloader.
- After the application returned, READY/Park/stationary was verified.
- The guided backend paused before its legacy Brake/FRC recovery checkpoints.
- No Brake reset and no FRC reset were performed.
- The waiting backend was terminated at that safe pause, releasing Panda.
- A read-only control-domain-state check and one oracle known-answer were then
  run with no peer resets.

Interpretation
Verified dynamically for this exact startup path: the old Brake/FRC restart
ceremony is not required after startup-caught direct-boot oracle installation
when the post-install control-domain state is already healthy. The normal
startup flow should therefore verify peer state and oracle KAT directly and
only retain peer-reset commands as explicit recovery tooling for an actually
unhealthy state, not as mandatory bringup steps.
