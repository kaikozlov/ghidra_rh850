# Camry `8965F3307000` reconstruction

This tree owns reconstructed C and retained original-byte scenarios. The target
registry's `decomp_root` selects it; tooling lives under
[`tools/targets/camry/decomp/`](../../tools/targets/camry/decomp/) and uses the
Toyota dispatcher, not a separate command surface or target registry.

## Commands

```bash
tools/toyota decomp --help
tools/toyota decomp status
tools/toyota decomp source memcpy_forward
tools/toyota decomp source 0x79044
tools/toyota decomp corpus
tools/toyota decomp oracle
tools/toyota decomp lift report
tools/test plan camry_decomp
tools/test camry_decomp
```

`status` validates the registered image hash, size, and non-overlapping symbol
ranges. It does **not** compile the C into a byte-identical RH850 image.
`equivalent` means agreement with retained scenarios, not every possible input
or physical vehicle behavior.

`source NAME_OR_ADDRESS` prints the canonical symbol, repository-relative path,
and reconstructed body. It accepts an exact canonical name or hexadecimal entry
address. A missing body is an error, not a fallback to Ghidra or a candidate cache.
Use `tools/pseudo --target camry-8965F3307000 NAME_OR_ADDRESS` for Ghidra pseudocode.

`corpus` generates and compiles disposable candidates. It copies checked retained
bodies verbatim and converts other Ghidra bodies, updating only unverified
statuses—not canonical sources or declarations. `oracle` compares candidates
with original-byte execution and publishes only agreements. Successful promotion
updates the retained bank and its declarations together; rollback restores both.
`lift report|emit|check` exposes instruction lifting through the same dispatcher.

## Source and evidence ownership

Function and data names are target-local; the registry and directory carry
calibration identity.

| Path | Owner |
|---|---|
| `symbols.jsonl` | Canonical function names, addresses, ranges, and signatures; shared with Ghidra seeds and pseudocode lookup |
| `data.jsonl`, `struct_layouts.json` | Curated named data and recovered type layouts |
| `oracles.jsonl` | Retained original-byte machine scenarios |
| `matched.jsonl` | Pipeline-maintained verification status and native ABI/form selection |
| `include/camry.h`, `include/ghidra_types.h` | Curated native ABI and Ghidra scalar types |
| `include/common.h` | Shared canonical declarations, regenerated with promoted C; do not hand-edit |
| `src/memory.c`, `src/leaves.c`, `src/nvm_rom.c`, `src/recovered.c` | Curated implementations and image-bound ROM definitions |
| `src/retained/<address>.c` | Promoted bodies in address-ordered 4-KiB entry windows |
| `src/retained/support.c` | Non-addressed helpers; never assigned fabricated firmware addresses |

Canonical lookup and retained verification read **retained bodies < curated
`src/*.c` definitions**, without a candidate cache. Oracle preparation explicitly
opts into candidates for unchecked names; cached candidates never replace
checked retained bodies or curated owners.

Retained filenames are eight-digit hexadecimal window starts: entry `0x49e22`
belongs to `src/retained/00049000.c`. Bodies are ordered by entry and name.
These buckets deliberately do not assert unproven subsystem ownership.

Generated workspace output belongs under the standard build output, normally
`build/out/targets/camry-8965F3307000/decomp/`:

- `candidates/`: candidate C and temporary declarations, regenerated by `corpus`.
- `lifted.c`: instruction-lift backend, regenerated by `lift emit`.

These are not tracked sources or `tools/artifact regen` artifacts. Only explicit
lift builds include the instruction backend; its presence cannot affect ordinary
C builds. Retained `form=lifted` checks regenerate it from registered inputs.
Do not hand-edit generated shards. Their key is `entry_address >> 14`:
`012.c` covers `0x48000..0x4bfff`; `3fafc.c` covers relocated Local-RAM entries,
not another CodeFlash image.

Statuses are `equivalent` after retained checks, `converted` after compilation
without those checks, or `unconvertible` after conversion/compile failure.
Do not hand-edit statuses to claim a passing result.

## Verification

`conversion/` owns Ghidra-to-C rewrites, `lifting/` owns instruction lifting,
and `execution/` owns the reusable native runtime—not test modules.
Gap thunks and full lifts share one compiled CPU runtime in `execution/host_cpu.c`.
`c_text.py` owns shared C scanning; `syntax.py` owns signature/scalar interpretation.

The local `camry_decomp` suite checks image identity, ROM bytes, retained
return/memory/register/call-sequence contracts, missing oracle coverage, source
selection, declaration compilation, and whole-bank/header rollback. It needs the
locked Python environment and a native C compiler. Event-driven scenarios also
need Ghidra machine timing replay when a local timing cache is absent; those
caches are workspace state, not portable evidence.

Keep canonical sources and scenarios as inputs. Promote Ghidra snapshots only
through the [project lifecycle](../../docs/WORKFLOW.md#rebuilding-the-complete-project-from-firmware).
